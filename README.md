# grok-imagine-mcp

MCP-сервер: Claude Code, Codex (и любой MCP-клиент) ставят задачи генерации **видео и картинок Grok Imagine**
через официальный API xAI и забирают готовые файлы на диск.

```
Claude Code / Codex  ──MCP (stdio)──▶  grok-imagine-mcp  ──xai-sdk──▶  API xAI (Grok Imagine)
   пишет промт, даёт фото                очередь задач                     ◀── видео/картинка
                                          + скачивание в папку
```

## Важно про оплату

API xAI оплачивается **отдельно** от подписки SuperGrok: по сообщениям сторонних источников, подписка не включает
API-кредиты. Ключ создаётся на [console.x.ai](https://console.x.ai), кредиты покупаются там же. Официальную документацию
xAI из среды разработки открыть не удалось, поэтому перед покупкой проверьте условия и цены на самой консоли.
Совет: завести отдельный ключ и поставить лимит трат. Фактическая стоимость генерации видео приходит в ответе
(`cost_usd`), если xAI её сообщает.

## Установка (Windows, PowerShell)

```powershell
cd tools\grok_imagine_mcp
python -m venv .venv
.\.venv\Scripts\pip install -e .
```

## Ключ

Положите ключ в файл `C:\Users\<вы>\.grok_imagine_mcp\.env` (создайте папку и файл). Так ключ лежит в одном месте
для всех клиентов и не попадает ни в конфиги клиентов, ни в git:

```
XAI_API_KEY=xai-...
```

Без ключа сервер всё равно стартует, а каждый инструмент отвечает, что надо сделать.

## Подключение к клиентам

Путь к Python — из вашего `.venv`. Синтаксис сверьте с документацией версии вашего клиента.

**Claude Code** (PowerShell):
```powershell
claude mcp add grok-imagine --scope user -- C:\путь\к\tools\grok_imagine_mcp\.venv\Scripts\python.exe -m grok_imagine_mcp
```

**Codex** — `~/.codex/config.toml`:
```toml
[mcp_servers.grok-imagine]
command = 'C:\путь\к\tools\grok_imagine_mcp\.venv\Scripts\python.exe'
args = ["-m", "grok_imagine_mcp"]
```

**Claude Desktop** — `claude_desktop_config.json`:
```json
{ "mcpServers": { "grok-imagine": {
    "command": "C:/путь/к/tools/grok_imagine_mcp/.venv/Scripts/python.exe",
    "args": ["-m", "grok_imagine_mcp"] } } }
```

Сервер работает на вашей машине и сохраняет файлы локально. Из облачной сессии Claude Code его не запустить.

## Как это работает в диалоге

Видео готовится асинхронно, поэтому схема из двух шагов:

1. Claude вызывает `grok_generate_video(prompt, …)` и получает `task_id` (статус `pending`).
2. Claude вызывает `grok_task_status(task_id, wait_s=45)`. Когда видео готово, оно скачивается в папку результатов,
   а путь приходит в `output_path`.

Картинки синхронные: `grok_generate_image` сразу сохраняет файл и возвращает путь.

Для «фото → видео» Claude передаёт `image_path` (абсолютный путь к локальному файлу) — например, к картинке,
которую он только что сгенерировал или сохранил.

## Инструменты

| Инструмент | Что делает |
|---|---|
| `grok_generate_video(prompt, image_path?, duration_s?, aspect_ratio?, resolution?, generate_audio?, model?)` | Ставит задачу: по тексту, а с `image_path` — из фото |
| `grok_generate_image(prompt, aspect_ratio?, resolution?, model?)` | Картинка, файл сохраняется сразу |
| `grok_task_status(task_id, wait_s=0)` | Состояние задачи; готовое видео скачивается на диск |
| `grok_list_tasks(limit=10)` | Последние задачи |
| `grok_status()` | Готов ли сервер и уходят ли генерации реально в xAI |

Допустимые значения (модели, форматы кадра, разрешения) берутся из `xai-sdk` и видны клиенту прямо в схеме
инструментов. Длительность — 1–15 с. `image_path` — PNG/JPG/WEBP до 10 МБ; расширение должно совпадать
с содержимым, произвольные файлы наружу не уходят. Ссылка на готовое видео у xAI действует 24 часа, поэтому
забирайте результат вовремя.

`wait_s` ограничен 50 секундами: у некоторых клиентов таймаут вызова инструмента короткий (в Codex он настраивается
параметром `tool_timeout_sec`), поэтому не блокируем вызов надолго.

## Настройки

Переменные окружения или строки в `~/.grok_imagine_mcp/.env` (реальное окружение приоритетнее файла):

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `XAI_API_KEY` | — | Ключ API xAI |
| `GROK_STATE_DIR` | `~/.grok_imagine_mcp` | Состояние: `tasks/` (по файлу на задачу) и `.env` |
| `GROK_OUTPUT_DIR` | `<GROK_STATE_DIR>/output` | Куда сохранять видео и картинки. Удобно указать папку проекта |
| `GROK_DRIVER` | `xai` | `dry-run` — только записывать задачи, ничего не отправляя и не тратя; `web` — Grok Imagine через окно Chrome по подписке, без ключа (см. ниже) |

## Драйвер web: Grok Imagine по подписке, без API-ключа

Драйвер `web` управляет страницей `grok.com/imagine` в отдельном окне Chrome. Это то же самое, что вы делаете руками,
только по команде из Claude Code или Codex: текст → видео, фото → видео, текст → картинка. Файлы сохраняются в
`GROK_OUTPUT_DIR`. Инструменты те же, что у драйвера `xai`.

**Включение.** Добавьте строку в `~/.grok_imagine_mcp/.env` (ключ не нужен):

```
GROK_DRIVER=web
```

**Первый вход.** При первой генерации сервер сам откроет окно Chrome с профилем `<GROK_STATE_DIR>\chrome-profile`.
Войдите в Grok в этом окне вручную (Google, X или почта) и повторите запрос. Сессия хранится в профиле. Сервер
никогда не вводит логин, пароль и коды и не принимает согласия на странице.

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `GROK_WEB_PORT` | `9340` | Порт отладки окна Chrome (только `127.0.0.1`) |
| `GROK_CHROME_PROFILE` | `<GROK_STATE_DIR>\chrome-profile` | Профиль Chrome для Grok |
| `GROK_CHROME_PATH` | автопоиск | Путь к `chrome.exe` |
| `GROK_WEB_GENERATION_TIMEOUT_S` | `900` | Сколько ждать одну генерацию |
| `GROK_WEB_QUEUE_TIMEOUT_S` | `900` | Сколько ждать очередь к окну (Claude Code и Codex делят одно окно) |

**Что поддерживается.** Длительность 6, 10 или 15 с; разрешение 480p, 720p, 1080p (если позволяет ваша подписка);
формат 2:3, 3:2, 1:1, 9:16, 16:9; звук вкл/выкл. С фото формат берётся из фото, `aspect_ratio` игнорируется. Поле
`model` не применяется. Недопустимые значения отклоняются с перечнем допустимых. Один запрос картинки Grok превращает
в сетку из 10 и более картинок (режим «Количество изображений: Авто»): сохраняется первая, об остальных сказано в
примечании к задаче. Такой запрос тратит лимит подписки заметнее, чем видео 6 с. Качество и число картинок драйвер не
задаёт.

**Риски.**
- Пока окно открыто, любая программа на этом компьютере может управлять вашей сессией Grok через порт отладки.
- Автоматизация веб-интерфейса подписки может не соответствовать условиям xAI.
- Смена вёрстки grok.com ломает драйвер. Подписи элементов русские, при другом языке интерфейса может потребоваться
  правка таблиц в `grok_page.py`.
- Генерации идут по одной, остальные ждут в очереди.
- Окно, которое открыл сервер, может закрыться вместе с клиентом, если клиент завершает дерево процессов (MCP SDK на
  Windows так и делает). Вход в Grok хранится в профиле, поэтому следующая генерация откроет окно заново, а видео,
  прерванное закрытием окна, доводится по `post_id` при очередном `grok_task_status`. Картинку, прерванную таким
  образом, придётся запустить заново.
- Окно запускается с `--disable-features=CalculateNativeWinOcclusion`: без этого окно, закрытое другим окном, Windows
  считает скрытым, и Grok не рисует в нём меню. Окно, открытое вами вручную без этого флага, под другими окнами
  работать не будет: сервер скажет «окно Chrome скрыто», закройте его, и сервер запустит своё.

Живая проверка на вашем аккаунте (расходует лимит подписки):
`$env:GROK_WEB_LIVE='1'; .\.venv\Scripts\pytest tests\test_web_live.py -s`.

## Разведка десктоп-приложения Grok (справка)

Скрипт `python -m grok_imagine_mcp.recon` (Windows) определяет, чем управлять приложением Grok. На практике
«приложение» Grok на Windows оказалось установленным веб-приложением Chrome (`chrome_proxy.exe --app-id=…`), у которого
нет ни отдельного `.exe`, ни порта отладки, поэтому разведка отвечает `not-running`, даже когда окно открыто. Для
работы по подписке используйте драйвер `web` выше.
